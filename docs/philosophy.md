# Philosophy (working draft)

The operator's design arguments, kept as one running table, refined statement by
statement. Working draft — feeds `site/index.html` and `docs/rationale.md`
once settled.

| # | Axis | Rule | Split / Value |
|---|---|---|---|
| 1 | Compressed pool contents | Only cold pages may live compressed — danger is which pages end up there, not how big the pool is | — |
| 2 | zram vs zswap | Branches on mass-storage speed, checked at config time (not runtime auto-probe) | fast storage → zswap; slow/no storage → zram |
| 3 | zram resident cap | Linux `mem_limit` rejects block writes with `ENOMEM` once crossed; it is not a graceful physical budget | **Removed and refused.** nixram leaves zram physical residency unlimited beneath `zram-size`, rejects a downstream nonzero cap at evaluation, and lifts stale live caps to 0 without swapoff. zswap max-pool-percent is a separate cache policy backed by real swap. `rationale.md [2]` |
| 4 | Compression algorithm (primary + recompression) | Architecture split — **the operator's explicit instruction**: "everything up to a GB goes to zstd primary and done"; lz4-then-recompress is a narrow, uncertain exception "only for the weakest of weak CPU bound machines," not the default for the whole small-tier band | **Built, corrected back to the explicit instruction.** **256M/512M/1G** — `zstd(level=3)` primary, no recompression at all. **2G-128G** — `lz4` primary + `zstd(level=3)` recompression. An earlier version wrongly gave 256M/512M the lz4+recompress architecture, over-applying the operator's narrow "weakest of weak" exception to the whole dire band — a real implementation error, caught directly ("I see you are still disobeying") and reverted. Why the split falls at 1G/2G rather than headroom-based reasoning: **workload compute-boundedness**, per the operator directly. 256M-1G see light, few-user usage with no CPU contention, so paying zstd's cost synchronously is free and grabbing density immediately matters more than waiting ("you need to get whatever you can"). 2G+ increasingly runs compute-bound workloads (LLMs/genAI/many apps) competing for the same CPU a dense primary would consume, so the cheap primary protects that live demand and the expensive pass is deferred to idle time ("you can wait for it later"). Directed, quoted in full in `rationale.md [9]`. Placing the boundary exactly at 1G/2G (rather than the operator specifying every tier) is this project's own inference. Never step down to level=1. `levels.nix`, `rationale.md [9]` |
| 5 | Backstop watchdog (last resort) | PSI-based (`memory.pressure` full/avg10 vs threshold, accumulator over the duration window) — confirmed scale-invariant by formula (no RAM/byte term), not just convention; the only genuinely RAM-dependent piece is whether to run the daemon at all (256M's fixed RSS tax vs variable budget), a resource-budget question, not detection-scale | **Built.** 60% flat at every tier — already correct: the real systemd-oomd upstream default, not NixOS's own 80% module default (whose claimed Fedora origin doesn't match Fedora's actual 50%/20s). Duration is 30s shared across every zram tier, but `mode = "zswap"` shortens it to 3s specifically — directed, to react faster under a bursty LLM-compute workload; the 60% threshold itself is unchanged. This is the one place the "zram/zswap share the number" stance didn't hold up once checked against the real host data point it's supposed to be grounded in (`modules/oomd.nix`). Protection already complete: `OOMScoreAdjust=-900` + `ManagedOOMPreference=omit` both set (`modules/oomd.nix`). zram/zswap share the threshold, not the duration or the severity behind it — added `oomd.pressureDiagnostics.enable` (`modules/oomd.nix`, `modules/default.nix`), on by default for `mode = "zswap"`: logs `memory.pressure` + `io.pressure` together, diagnostic only, never wired into the kill decision. Full writeup: `rationale.md [10]` (extended) and new `[14]` |
| 6 | Recompression: keep or drop, and when it runs | Long target uptime means the background recompression cost has time to pay off. Cadence should be "whenever there is idle time" (the operator's explicit call), not a fixed calendar — a busy box shouldn't be forced to run it, and a quiet box shouldn't only get one chance a day | **Built.** Off at 256M/512M/1G (zstd-alone primary already dense, row 4); on from 2G up. Cadence: timer checks every 15 min (`recompressionTimer.onCalendar`, now a check-frequency not a run-frequency), gated on CPU PSI (`/proc/pressure/cpu` "some" avg10 < 10%) — acts only when genuinely idle, skips and retries otherwise. `modules/zram.nix`, `rationale.md [11]` |
| 7 | Swappiness | Medium-cost ratio is only half the story. Actual RAM pressure and available file cache decide when anonymous reclaim is useful | **Built.** 120 at 256M/512M/1G. 10 at rest, relief-gated up to 60 under genuine sustained pressure at 2G-128G. zswap uses 25. `modules/sysctls.nix`, `modules/zram.nix`, `levels.nix`, `rationale.md [3]`, `[17]` |
| 8 | Watermarks | `boost_factor=0` flat: confirmed, even more clearly justified on small zones (kernel's own bug history — boost is *more* dangerous there). `scale_factor` taper: small-tier boost (200) has real indirect support (`min_free_kbytes`'s sqrt-scaling eats proportionally more of small tiers' headroom); large-tier reduction to 100 has no support found anywhere, and one data point argues the opposite (the mechanism's own motivating case was 140GB *servers* needing MORE headroom) | proposed correction, pending confirmation: keep 200/150 at small/mid tiers, flatten 64G-128G back to 125 (the one sourced anchor) instead of the current 100 — looks like an unsupported, possibly backwards extrapolation |
| 9 | MGLRU `min_ttl_ms` | Kernel doc explicitly calls being "agnostic to... memory sizes" a deliberate design virtue — cleanly confirmed flat, no RAM-size caveat needed | **Measured, and the value changed: 0 flat, the kernel default.** The flat SHAPE held — the knob really is size-agnostic, and the failure it caused is identical at 456 MiB and at 125 GiB. What did not hold was 1000ms. The oomd-interaction flag asked for a tracked experiment; production supplied one on two hosts at opposite ends of the range, and the "no oomd" wording turned out to be a warning after all, not an audience statement. `min_ttl_ms` calls `out_of_memory()` directly from `kswapd` on generation age, not on scarcity: four kills of production workloads on corbet-server with **74 GiB free** and `all_unreclaimable? no`, 263 kills in one boot on vultr through the same path. Running it alongside a watchdog does not make it complementary, it adds a second killer with an unrelated trigger. `rationale.md [7]` |
| 10 | CPU class as a second dimension | Investigated and rejected as a formal axis. RAM tier doesn't reliably predict CPU headroom (real counterexample: same-tier container on a many-core host vs. a single shared vCPU cloud box) — the instinct is sound. But "shared vs. dedicated" conflates two different properties (per-core speed vs. contention/steal-time), and unlike RAM, CPU class has no stable, checkable ground truth — for a container it can change with zero config edit (noisy neighbor co-scheduled) | **Superseded by row 11** — the actual answer wasn't a CPU-class axis, it was true-RAM-headroom, which nixram already knows per-level without inferring anything. `compressionAlgorithmOverride` still exists as a general escape hatch but is no longer expected to be commonly needed |
| 11 | True RAM headroom, not RAM tier or CPU class | Swappiness depends on actual RAM pressure and available file cache; recompression architecture depends separately on workload compute-boundedness | **Built.** 256M-1G=zstd(level=3)-alone/no-recompress+swappiness 120+`zram-size=ram`; 2G-128G=lz4+recompress+swappiness 10-at-rest/relief-gated+`zram-size=ram*75/100`. The exact relief thresholds remain extrapolated. |
| 14 | Swap should be for overflow (deploys, bursts) or icecold pages, not routine fullness | The operator directly: "expect the servers to be stuffed to 80% or so and we don't want them to start swapping just because. Swap is for overflow when upgrades run or whatever, or for icecold pages." A static swappiness number, however low, can't distinguish "routine fullness" from "genuine overflow" — it needs a live signal, the same shape as the CPU-PSI idle gate already used for recompression (row 6), applied to memory pressure instead of CPU idleness | **Built.** `zram.swappinessRelief`: a systemd timer (default every 30s) reads `/proc/pressure/memory`'s "some" line. Enters relief (swappiness → 60) when `avg10` >= 10% (fast signal, catches a real spike quickly); leaves relief (swappiness → the tier's 10-at-rest baseline) only when `avg60` < 1% (slower signal, deliberately harder to satisfy, so a brief lull mid-spike doesn't bounce swappiness back down early). On by default only on reluctant tiers (2G-128G) — dire tiers are already eager, nothing to relieve. State tracked under `/run`, cleared every reboot. Unvalidated starting point for every threshold; tune freely. `modules/zram.nix`, `modules/default.nix`, `rationale.md [17]` |
| 12 | The 768M gap: rounding into a discrete policy cliff, not just a percentage — added, then removed | The ladder briefly gained a 768M anchor while 512M and 1G differed in architecture | **Removed as redundant.** The later corrections made 512M and 1G identical: `ram` logical capacity, zstd(level=3)-alone, swappiness 120, watermark 200, oomd=true. A 768 MiB host rounding to 1G therefore gets the same policy without a separate anchor. `levels.nix`, `checks/default.nix`, `rationale.md [16]` |
| 13 | zram-size logical capacity | `zram-size` is the sole safe capacity ceiling. It allocates no RAM up front; real use depends on compression. A nonzero `mem_limit` is not a second safety budget because Linux rejects block writes with `ENOMEM` when it is crossed | **Built and adversarially corrected.** `ram` at 256M-1G; `ram * 75 / 100` at 2G-128G, including the directed 96 GiB endpoint at 128G. nixram emits no resident limit, rejects a downstream nonzero one, and safely lifts stale live caps in place. `levels.nix`, `modules/zram.nix`, `rationale.md [1]-[2]` |
